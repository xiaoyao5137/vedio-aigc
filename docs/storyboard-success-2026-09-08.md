# 场景短分镜成功率修复

最新失败记录是 `record-psw369`，2026-09-08 12:40:32 停在第一轮“场景短分镜”。5 次文本模型请求都成功返回，本地分镜校验在约 104 秒后拒绝候选。

## 根因与调整

1. 前 4 轮使用正常的 `0.0秒-1.0秒`，旧解析器识别为 0 段，真实的 1.0–1.5 秒缺口直到第 5 轮才暴露。统一分镜、语音、表演预算、采样及媒体证据的时间解析，兼容两端秒单位、不同分隔符和括号；保留所有原始数值，不用格式归一化掩盖缺口或重叠。错误提示逐项列出具体区间。
2. 原候选含完整旁白，但“保持伏案姿态”仍被正则判成超过 1.2 秒的无声空等。姿态保持、建议 3–6 段和建议 650 字符现作为 `scriptValidation.warnings` 保存，不触发重写。实际缺台词、剧情覆盖缺失、错误人物承接、伪造 observed 状态、时间轴不连续、自然语速放不下及模型容量限制继续阻断。
3. 合法活动窗口已经给出完整计划时，程序计算 action/reaction 秒数和 performance overlapWith，记录修改路径。不会移动窗口、改台词、删动作或补造缺失的活动。现有时间拉伸也不能自动吞掉原始缺口。
4. 修复提示同时描述预算与时间轴问题，不将算术不一致解释为空等。拆镜与网络重试共用生成额度；额度耗尽时保留原缺陷和网络错误，不用空诊断或额度提示覆盖原因。未增加调用上限。

完整视频请求在模型适配层仍保留 2500 字符上限检查；650 字符仅是分镜正文的编排建议。脚本校验通过表示计划可执行，不能作为实际成片质量结论。
