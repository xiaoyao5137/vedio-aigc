# 人物聚合资产与工作流召回规格

**状态：** 功能已落地，自动测试与现场读取验收通过；真实装备资料与成片人工验收待录入/执行

**日期：** 2026-09-28

**范围：** 人物资产库、持久化接口、三国历史短剧现有工作流的人物检索及下游素材绑定

## 问题与现状

人物库目前按每张三视图逐行列出。相同工作流中的同名人物有多个年龄或造型版本时，需要逐行寻找；装备没有明确的人物级归属和召回契约。现有 `character_assets` 保存每张三视图，`character_biographies` 按工作流与人物名共享生平；`character.lookup` 已按显式年龄、造型及集数过滤，但没有把人物与装备一起组织。2026-09-28 的现有库读取结果为 99 张三视图、70 个工作流/人物组合，其中仅 7 张带有明确年龄与造型上下文。这是存量事实，不能据人物名为其余旧图补写年龄、场景或装备。

## 目标与范围

- 人物列表中每个工作流内的同一人物只占一行，人数统计和分页均按人物计算。
- 人物详情展示该人物全部三视图版本，清楚标出年龄阶段、适用剧情时间和稳定场景造型，并能维护其装备。
- 工作流以当前分镜明确的人物、年龄、场景造型及装备需求召回正确版本和装备，向生成节点传递可核对的资产 ID；缺少匹配时走原有缺失资产分支或明确报错。
- 保留原三视图 ID、图片、元数据、生平、声音、已付费素材、执行记录及未完成的人工审阅。旧 `/api/characters` 平铺接口继续可用。

本次没有依据文本猜测现有装备，也不自动把旧图改标为某个年龄；仅结构化存储用户或工作流明确确认的装备资料。

## 用户与场景

人物库维护者在同一人物的详情中检查青年、壮年、不同服装的素材并维护其装备。工作流操作者在某段分镜中确认人物造型与持有装备，复用已有资产继续生成镜头。历史执行的审阅者仍可按原三视图 ID 核对旧结果。

## 非目标

不凭人物名或剧情文本推定真实年龄、实际持有武器或人审通过状态；不重新生成已有三视图、修改历史执行快照或自动购买新媒体。

## 数据与接口契约

**人物身份。** 以 `(workflowId, trim(characterName))` 区分。不同工作流的同名人物彼此独立；旧的未关联工作流人物保留在独立身份中。一个人物的 `versions` 是既有 `character_assets` 三视图行；删除一个版本不等于删除整个人物或其他版本。人物 `id` 为从身份元组确定性产生的不透明 ID，不依赖某张图片。

**三视图版本。** 每个版本保留自身 ID、图片、说明、修订号和原 `metadata.visualContext`。年龄阶段、年龄依据、岁数区间、剧情时间及 `look.key`/描述继续沿用现有校验。无标注旧版显示“未标注”，不能匹配明确的年龄/造型要求。场景造型表达稳定服饰；镜头动作和背景不写进三视图身份。

**装备。** 装备归属于人物，字段包含 ID、名称、类别、描述、可选图片、别名、适用年龄阶段、造型键、场景标签及更新时间。装备可与多个三视图版本共同使用；明确限制的装备只在满足相应条件时召回。删除三视图版本不删除装备，删除装备不更改原图片或历史执行。装备图片是独立素材；空图片可表达只有文字资料，不能冒充已有视觉附件。

**读取与维护。** 新增 `GET /api/character-people` 返回 `{people:[{id,workflowId,characterName,biography,versions,equipment,updatedAt}]}`；装备由 `/api/character-people/:personId/equipment` 的新增，以及带 `:equipmentId` 的修改和删除接口维护。`/api/characters` 及其三视图 CRUD 保持原行为。接口拒绝跨人物修改、非法类别/适用条件或找不到的人物，错误不得造成部分入库。

## 工作流契约

人物召回使用分镜里可追踪的明确人物与视觉条件。选择次序为用户对本集明确指定的三视图、同人物中满足年龄/造型/集数及实际图片门槛的归档版本、原有缺失人物生成分支。手工指定错人物、错工作流、图片不可用或与已批准视觉条件冲突时，在付费媒体请求前终止。不得把“最新版本”当作任意场景的默认匹配。

装备需求应来自结构化分镜或明确输入；新生成的场景和分镜必须显式给出装备数组，空数组表示本段没有明确需求。召回同时核对装备所属人物、名称/别名、年龄阶段、造型键和场景标签。结果携带装备 ID、名称、描述及可选图片 URL；首帧依据已批准分镜中的装备描述构图，视频提示携带装备归属、名称、描述和 ID。装备图片 URL 留在执行记录供核对，不占用人物三视图参考图的供应商容量。没有明确装备需求时不自行给角色加武器；剧情明确要求却尚未入库的装备仍保留原名，并在召回处阻断和提示补录。明确要求的装备不存在或不适用时，停止素材购买并给出可处理的缺失原因，不能悄悄替换成别的武器。

新工作流模板与已经保存的三国工作流均需更新人物召回节点和消费它的下游节点；迁移仅更新这部分受管字段，保留其余节点、连线、模型配置、运行输入和执行记录。旧执行快照仍按原资产 ID 可读，续跑不能把新聚合 ID 误当成三视图 ID；从旧快照跳到付费视频节点时，须重新核验执行中绑定的装备仍存在且归属、名称和适用条件有效。

## 验收标准

- **AC-001** — 验证 FR-001：给定两张不同年龄/造型的同名三视图，搜索与分页只出现一人；其他工作流同名人物另占一行。
- **AC-002** — 验证 FR-002：当打开详情并切换两个版本，则图片、年龄和造型均对应原 ID；旧版不被虚构年龄。
- **AC-003** — 验证 FR-003：当新增适用范围不同的武器与配饰并刷新，则仍在同一人物详情；编辑/删除只影响目标装备，三视图和生平不变。
- **AC-004** — 验证 FR-004：当青年便服与壮年甲胄分别请求召回，则各返回对应 ID；不匹配和旧未标注版本不误用，显式选择冲突时报错。
- **AC-005** — 验证 FR-005：当分镜明确要求武器 A，则召回和下游引用均指向 A；同名别人物装备、过期场景装备及未要求的武器均不能代入。
- **AC-006** — 验证 FR-006：当指定不存在或不适用的装备，则节点返回明确错误、媒体模型调用数为 0，已有资产与执行记录保持。
- **AC-007** — 验证 NFR-001：当重复初始化/迁移，则不会重复创建人或装备；基线图片与执行记录保持，旧 API 仍返回平铺版本。
- **AC-008** — 验证 NFR-002：当仅用键盘和窄屏打开详情与装备编辑，则所有操作仍可完成，无不可操作的横向截断。

## 状态、异常与可观测性

人物可能只有生平、装备、一个或多个三视图；这些身份应可在聚合结果中找到。三视图与装备分别有自己的增删改状态。无匹配、资料无效、跨工作流 ID、图片不可读及人工审核中状态须分别表现，不能统一显示为“已通过”。日志/收据应能记录人物 ID、选中三视图 ID、装备 ID、筛选/拒绝理由、是否发生媒体请求；不记录私密凭证。

## 迁移、回退与限制

人物聚合通过读取既有行构建；新装备表为增量结构，不重写旧图或历史记录。已保存工作流先备份配置，再有目标地更新人物召回契约，并核对节点/连线与执行记录数量。若新召回出现错误，可恢复该配置备份；装备表和原三视图不随配置回退而删除。视觉准确性仍需对实际图片与视频做人审；技术召回成功不代表人物外观或武器呈现质量已获人工认可。

## 风险与处理

现有人员身份由工作流和人物名组成，因此更名或跨工作流改归属会影响生平、声音和装备的身份键。编辑现有三视图时禁止悄悄改变这两个字段；确需迁移身份时应单独审计并迁移关联资料。旧三视图缺少年龄/造型标注，会降低自动命中率；应提示人工补录，不能用不可靠的默认值补齐。装备有图片但分镜没有明确使用要求时，不向画面自动添加武器。

## 决策与待确认边界

当前采用工作流 + 人物名作为逻辑身份，是对现有生平和声音共享方式的兼容选择。同一工作流中确有“同名但不同角色”的情况时，需要为该角色提供独立身份键，再迁移对应资产，不能依赖名称自动合并。既有 99 张图不自动推定装备；真实装备图片、命名及适用范围由后续实际资产录入决定。

### 2026-09-28 后续增量验收

上文的 99 张三视图、0 件装备和工作流 schema 154 是首次验收时的基线，予以保留；以下为同日后续变更的现场读回，不回写或改称首次验收结果。

- 已保存的三国工作流随后升级至 schema 155，补全人物传记的正史来源提取与存量人物独立补证路径：已有三视图不再阻断传记补全，已有史料可复用；检索失败与确无记载分别标识，自动占位文本按原值条件更新并保留人工补充。当前生产工作流又因独立的镜头覆盖门禁迁移升级至 schema 156，schema 155 的传记节点变更仍在其中。
- 人物聚合接口后续读回为 70 人、100 个既有三视图版本。张飞占一条人物数据行，详情保留 6 个版本，其中 2 个当前可用、4 个历史版本；人物级“张飞原创”声音随该人物返回。历史版本可查看，不参与默认三视图召回。
