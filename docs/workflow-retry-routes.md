# 可编程分支路由

之前的回退虚线由 `acceptance.retryFrom` / `errorRetry` 自动绘制，用户不能手动创建这种控制边。现在已替换为实际的“分支判断节点”和持久化连线，旧配置仅用于一次性迁移，不再驱动运行器。

## 手动编排

1. 从节点面板新增“分支判断节点”。
2. 从质检节点输出端口拖线到分支输入端口。需要每轮执行时，在“所属循环”中选择循环；选择“循环外”可移出循环。
3. 从分支的 true / false 端口分别拖线到目标；也可以在节点属性的两个“出口目标”下拉框里连接、改接或断开。两种方式编辑的是同一条实际连线。
4. 编辑分支 JavaScript 和参数。目标可以是后续节点、之前的节点、自身或其他循环范围内的节点。每个出口对应一个目标。

分支连线随工作流保存、复制。向前分支只运行被选中的路径，跳过另一条路径并保留共同汇合节点。回跳恢复目标执行前的上下文并重建后续执行；旧候选、输入和路由事件保留在执行记录中。回跳循环入口会重新展开循环，进入尚未展开的循环子节点会先运行其所属循环入口。

同一节点有多个循环实例时，优先路由到当前轮实例；跨循环则选择最近的已执行实例，没有已执行实例时选择首个待执行实例。空循环的子节点通过所属循环入口重新展开。

连线不能指向不存在的节点。普通依赖线仍不能组成环；需要回路时，从分支出口连线。回路不再被当作普通 DAG 循环依赖。

## 分支代码与次数

`context` 提供前序输出，`params` 提供用户定义参数。代码可返回 `true`、`false`，或者 `{ value: false, feedback: ... }`。`feedback` 会成为路由目标的 `retry.feedback`。需要明确修改回跳后的上下文时，可返回 `contextPatch`。

```js
const report = context.quality_report;
if (typeof report?.passed !== 'boolean') throw Error('质检结果缺失');
if (report.passed) return true;
const limit = Number(params.maxAttempts);
if (!Number.isInteger(limit) || limit < 1) throw Error('上限必须是正整数');
if (branch.counts.false + 1 >= limit) {
  throw Error('达到上限，可修改 maxAttempts 后重试本分支');
}
return { value: false, feedback: report.issues };
```

`branch.visits` 是当前分支已经完成的路由次数；`branch.counts.true/false` 是此前选择各出口的次数。代码抛错会停在分支，既不增加成功路由次数，也不执行目标。运行器不解释 `maxAttempts`：它只是上例自行定义的参数，可以改名、删除或改成其他判断逻辑；true/false 任一出口均可回跳。

每轮循环有自己的计数；外层回路重新运行内部分支时，内部分支从新的一次处理开始。决定回跳的分支保留自身计数，即使回跳重建了所属循环。参数覆盖和分支计数一起进入执行检查点。

## 达到上限后继续调试

选中失败的分支，在“分支调试变量”中修改 `maxAttempts`（或代码使用的其他参数）。点击“从此节点重试”，仅重新执行分支判断，保留当前质检证据和已有路由计数。判断选择回跳后，运行器停在目标的待执行位置；可点“下一步”或“运行到下一断点”继续。

调试变量只覆盖本次执行，不覆盖工作流模板；刷新后仍保留。代码中的参数引用会重新解析，用户也可编辑该分支的输入上下文。旧执行记录需要升级时保存为新恢复记录，原始记录保持不变。

## 三国工作流

原有四组隐式重试已拆为 8 个显式分支：每组先判断质检是否异常，再判断结果是否通过。报告异常回到审查节点，内容拒绝回到对应生成节点，具体目标与次数都由分支代码、参数和真实连线决定。成片结果分支的 false 出口连接“参考生视频”，true 出口连接“尾帧结果整理”。

运行 `node scripts/migrate-branch-routing.mjs [工作流ID]` 可迁移其他旧策略工作流。脚本先保存数据库行备份，再事务更新节点和连线；重复执行不会重建用户已修改的分支。界面加载旧配置也会应用同一迁移。
