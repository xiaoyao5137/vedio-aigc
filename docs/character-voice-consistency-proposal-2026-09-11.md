# 人物音色绑定与跨分镜复用方案

状态：用户已授权实施；原生可灵绑定主链路已实现，完整验收未完成。更新：2026-09-12。原始设计及调查基线保留如下；当前实现与验证状态见 `character-voice-implementation-2026-09-12.md`。

## 问题与现状证据

用户反馈同一人物在多个生成分镜中的音色不一致，影响连续观看时的人物辨识与可信度。本次核查了代码，未抽听实际视频，尚未定位某次具体执行的变声片段。

- `src/CharacterLibrary.tsx` 的人物资产及编辑表单包含姓名、描述、三视图、版本及 metadata，没有专门的声音绑定或试听流程。
- `server/builtin-nodes.ts` 的 `lookupCharacterAssets` 按姓名、工作流、continuityKey 查找三视图，不能直接承担稳定的声音身份管理。
- `src/workflow-core.ts` 与 `src/duration-schedule.ts` 已有说话人、台词、声部和时间调度约束，但这些约束不等于固定音色。
- `server/model-adapters.ts` 的 `buildKlingVideoRequest` 发送 sound 开关，没有人物音色 ID 或参考音频绑定字段。这说明当前适配层没有接入，不能据此断言供应商不支持。
- `server/builtin-nodes.ts` 的 `buildTimeline` 区分 external / video-native 音频来源，返回待渲染清单，并非实际完成分轨、换声、混音与口型同步的证明。
- `server/local-model.ts` 的本地音频输出为模拟静音 WAV，不能作为音色能力或验收证据。

## 用户与场景

面向在人物库维护角色、运行多分镜短剧的创作者。典型场景：首次给曹操选定声音；连续多个镜头复用；多人轮流对白；同一人物愤怒或低语；单镜重试；执行中修改人物资料；修复历史成片。

## 目标与建议决策

将声音身份与人物身份绑定，将情绪和语气留给每句表演。相同角色跨镜头、跨场景、重试时使用同一份声音版本；最终输出仍需实际听感与媒体验收。

推荐采用「人物声音资产 → 执行声音快照 → 分镜逐句绑定 → 能力路由 → 成片音色检查」链路。默认正式生成要求声音绑定完整；预览可使用文本音色描述，但必须显示“音色未锁定”。

## 非目标

首版方案阶段只做设计；后续用户已授权实施，并进行了隔离的真实生成验证。不承诺通过一段文字或相同随机种子保证声音一致；不在首期覆盖所有供应商、合唱与歌唱模型；不自动重做历史成片。

## 方案选型与生成接口

| 路径 | 适用条件 | 处理方式与边界 |
| --- | --- | --- |
| 原生固定声音 | 实际模型、版本、端点已验证支持人物声音绑定 | 每句或每个说话人传入固定声音引用。保留原生表演与环境音；仍检查实际成片是否串角或变声。 |
| 固定音色配音＋口型同步 | 原生绑定不可用，且独立配音与口型处理链路已验证 | 先按人物生成台词音频，以实际时长校准节拍，再进行视频生成/口型同步与混音。多人镜头需支持对应人物的嘴部处理。 |
| 文本描述音色 | 探索或低成本预览 | 自动注入同一份音色描述，显示未锁定；不能用于严格一致性交付。 |

这里的条件均为拟接入能力，不是已确认的外部产品规格。实施前必须针对当前账户可用端点核查官方接口，并实测声音复用、多人物映射和口型效果；未完成验证的能力状态为 unknown。

能力按 provider/model/version/endpoint 维护：固定声音 ID、声音参考、逐角色绑定、外部音频驱动、多人支持及允许的引用数量。参考音频输入不自动等于声音克隆能力。路由只有在完整满足当前分镜所需能力时才可选；普通 TTS 的 voice ID 不得直接发送到视频端点。

外部配音路径不得直接在原有人声上叠加新声。必须使用可用的独立音轨，或完成经验证的人声去除/替换，并保留必要环境音、动作声和群体声部；出现残留原声、双重人声或音效损坏时不能验收。无法可靠替换时重生成受影响镜头或暂停该路径。

## 功能需求

- FR-001 — 人物库必须支持为人物选择、试听并保存一个声音版本，展示未绑定、待试听、已绑定或不可用状态。
- FR-002 — 系统必须以稳定 characterId 关联声音，不能把姓名、三视图地址或一次生成的音频地址当作身份主键。
- FR-003 — 正式执行必须在首次媒体生成前解析所有已知说话人的声音绑定并持久化不可变执行快照。
- FR-004 — 每个有词人声节拍必须解析到明确说话人及快照中的声音版本；无法解析或存在歧义时必须暂停该分支。
- FR-005 — 生成路由必须根据已验证能力选择路径；严格模式下不支持绑定的模型必须在付费请求前报出阻塞原因。
- FR-006 — 断点恢复与同镜重试必须沿用原执行声音快照，除非用户显式创建采用新声音版本的执行分支。
- FR-007 — 人物库修改声音必须产生新版本，并在应用到已有执行前显示受影响的镜头及其下游结果。
- FR-008 — 最终交付必须保存真实音色一致性检查结果，并允许 passed、failed、uncertain；未取得充分证据不得显示通过。
- FR-009 — 配音路径必须把实际台词音频时长反馈到节拍调度；超时必须调整排程或拆镜，不得为塞进时长删词或强制加速。
- FR-010 — 历史记录必须支持只读查看原素材，并由用户选择是否创建修复分支及重做范围。

## 人物库交互

人物详情增加“声音”区域：音色名称、声音描述、试听按钮、绑定状态与版本。录入途径为选择平台预置声音，或上传参考后通过已接入且支持的服务创建声音。上传参考本身只进入待试听状态，不能假装已经获得可复用的声音 ID。

试听使用统一中性台词，并补充该人物的一句实际台词；需要激烈表演时增加情绪试听。可推荐声音候选，但不能未经用户试听确认就把候选标为已选。声音一经选定，用户无需逐分镜配置。

分镜页展示“曹操 · 低沉男声 · v2 · 已锁定”。编辑情绪、语速、停顿不修改基础声音身份。更换音色通过人物声音版本操作，明确影响范围。

## 数据契约与状态

建议独立保存逻辑人物、声音资产和版本，而不是将供应商 ID 散放到提示词或图片 metadata 中。

| 对象 | 核心字段与语义 |
| --- | --- |
| Character | 稳定 characterId；现有图片资产关联它；defaultVoiceProfileId 为默认声音。换装或重画三视图不会更换声音。 |
| VoiceProfileVersion | voiceProfileId、version、displayName、description、previewAssetId、referenceAssetId、状态、创建来源；版本内容不可变。 |
| ProviderVoiceBinding | provider、accountScope、modelScope、providerVoiceId 或 referenceAssetId、能力验证状态；跨供应商 ID 不通用。 |
| ExecutionVoiceManifest | executionId、manifestVersion、角色 ID 到声音版本及选定适配绑定的映射、素材哈希、锁定时间。 |
| Utterance | utteranceId、shotId、beatId、speakerId、原文、voiceProfileId/version、表演参数、计划时间窗、实际音频时长与产物引用。 |

旁白使用独立 narrator 身份；配角使用稳定身份；群体欢呼等非语言声部保留 actorGroup，不能强塞进单人 TTS。歌唱、哭喊、笑声等需要单独验证能力；缺失时明确报能力不足或待复核，不能静音或改成普通对白通过。

兼容现有姓名形式的 actorIds：在编译入口建立当前执行中的姓名/别名到 characterId 的映射，要求唯一；逐步将下游结构化字段改用 ID，不强行改写用户台词。跨工作流复用必须显式引用同一逻辑人物，同名角色不得自动合并。

绑定优先级：已有执行固定快照 > 新执行的工作流角色选角覆盖 > 人物默认声音。分镜只覆盖表演参数。当前工作流动态发现的新说话人通过追加不可变 manifest 版本锁定；不得偷偷更新已有角色条目。

接口层扩展人物读写、声音试听与绑定查询，并增加共享 voice.resolve / voice.validate / voice.render 能力。名称为建议操作名，不表示当前已有端点。试听/克隆状态采用 draft → auditioning → ready，失败为 failed，过期或撤销为 unavailable；长任务持久化任务 ID，恢复先查任务状态，避免重复提交。

音频缓存键至少包含原文、声音版本、供应商与模型版本、语言、情绪/语速参数、参考素材哈希及合成策略版本。缓存的是同一次表演的产物，跨镜复用的是声音身份，不要求不同台词复用同一音频。重试键与请求产物绑定；任何影响声音的输入变化均使相关缓存失效。

声音素材与试听文件沿用项目访问权限，供应商密钥只留在服务端；正式运行引用持久化受控资产，临时 URL 失效时从资产重新签发。删除人物不破坏已有执行证据；撤销可用性后不得继续发起新的合成。

## 错误、质量与可观测性

建议错误码：VOICE_BINDING_MISSING、VOICE_IDENTITY_AMBIGUOUS、VOICE_PROVIDER_UNSUPPORTED、VOICE_ASSET_UNAVAILABLE、VOICE_DURATION_OVERFLOW、VOICE_CONSISTENCY_FAILED。界面说明缺哪个人物、影响哪些镜头、可执行的修复动作；绑定缺失和能力不足不能进入无效的自动重试。

- NFR-001 — 新声音版本不得改变旧执行快照及原始媒体文件。
- NFR-002 — 人物声音约束必须经结构化编译传给适配器；提示词长度处理不得悄悄丢弃绑定信息。
- OBS-001 — 每次请求保存执行、镜头、台词、声音版本、模型路径、任务与素材关联，可定位“第几个镜头实际用了哪个声音”。
- OBS-002 — 记录缺失绑定拦截率、路由能力不足次数、音色失败/不确定率、重试次数，以及新增耗时和费用；不凭空设定上线数值。

媒体检查分为：请求确实复用了同一身份、每句声音确实对应人物、成片实际听感一致。说话人相似度可用来辅助筛查，但需先以真实样本标定阈值；不能用一个通用分数替代听审。短句、耳语、歌唱、多人重叠和噪声片段证据不足时保留 uncertain。ASR 只辅助核对台词，不能证明音色或口型合格。

## 验收与追踪

- AC-001 — 对应 FR-001、FR-002：同一人物绑定并试听声音后重画三视图，验证声音保持原版本；同名但不同人物可选不同声音，互不覆盖。
- AC-002 — 对应 FR-003、FR-004：两人轮流对白与旁白跨三个分镜生成，核对每句请求映射；制造一个重名歧义或未绑定人物，验证媒体请求发出前明确阻塞。
- AC-003 — 对应 FR-005：用不支持逐人物绑定的测试适配器运行严格模式，确认无付费请求；仅当备用路径完整满足能力时才可切换，不得静默改成文本描述。
- AC-004 — 对应 FR-006、FR-007：第一镜完成后将人物声音从 v1 改为 v2，验证恢复与重试仍用 v1；创建升级分支后列明受影响镜头，新分支全部使用 v2，旧文件保留。
- AC-005 — 对应 FR-008：实际生成同一人物的中性、愤怒、低语片段及与另一人物的对话，连续播放并对照人物试听样本，验证无可感知换人或串角；检查报告保留人工意见和辅助指标，证据不足不得通过。
- AC-006 — 对应 FR-009：制造实际配音超过时间窗的案例，验证重新调度或拆镜，台词完整；最终视频逐句核对嘴部同步、结尾完整、原人声无残留、必要音效未丢失。
- AC-007 — 对应 FR-010：验证旧执行可以继续查看，不自动产生模型请求；选择修复时创建新分支并保留原始记录和素材。

工程验证先覆盖身份解析、版本快照、适配路由、缓存与恢复；媒体验收再使用同一组真实素材。单元测试通过和供应商返回成功都不构成声音一致性验收。

## 发布、迁移与回滚

- ROLL-001 — 第一阶段建立人物 ID、声音资产、试听与执行快照；旧人物标为未绑定，原执行保留旧行为和明确状态。此阶段交付资产管理能力，不能宣称已根治变声。
- ROLL-002 — 第二阶段针对当前实际视频端点验证原生绑定，优先打通一条完整严格链路；若不支持，评估并打通固定配音、口型与混音链路。真实三镜及双人场景验收通过后才开放正式使用。
- ROLL-003 — 第三阶段增加跨镜检查、定向重做与其他供应商绑定；已有执行升级均创建可追踪分支。
- ROLL-004 — 按工作流启用新契约。故障时暂停严格生成，保留旧素材和快照；旧预览路径可独立恢复，但不得把降级结果显示为声音已锁定。

## 风险与待决策

1. 当前供应商能力：需官方接口及当前账户实测决定能否保留原生声音路线；本方案未作支持承诺。
2. 参考素材或预置音色：建议首期先开放可验证的预置声音选择与试听，参考音色创建在供应商链路确认后接入。
3. 外部配音成本：增加口型、混音、时长回传和验证工作，可能改变生成耗时、费用及表演效果；需同素材小样比较后决定是否作为默认路径。
4. 历史成片：建议按用户选定的人物与镜头建立修复分支。首期不默认整集重做。

以上保留首版推荐设计。后续已获得实施授权并开始真实音视频验证；尚未完成的需求及验收边界以实施记录为准。
