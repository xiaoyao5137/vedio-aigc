# 生产工作流的原则质检策略

用户目标是顺畅生成，并允许按需回到节点重做。这个方向适合当前阶段。此前问题并非主要来自网络：分镜模型在多轮完整重写时不断破坏已有的预算或格式；质检又要求维护复杂的逐项证据结构，报告本身耗尽复核次数。单纯提高次数只会增加延迟和费用。

本次将工作流改为显式的 `principle-v1` 策略：

- 生成侧由程序归一化可确定的语音预算、合法时长和未知状态格式，保留原台词、人物、剧情、依赖及原始候选。真正缺失剧情、非法并行和超过供应商能力仍要求修复。
- 质检只拦截有当前证据支持的原则问题，例如历史主体或因果错误、核心剧情明显删改、错误主演、明显时代错误、不可用画面及大范围台词错误。具体问题仍走原有局部重做分支。
- 表情、手势、服饰微差、节奏、尾部余量、采样未知及报告格式问题只显示建议。主成片审看直接使用实际抽帧和ASR，逐帧观察和逐要求重复审核在该策略下跳过。
- 报告请求可恢复临时传输或JSON错误，最多20次仍不可用时保留明确的未审核状态；上游传输已耗尽20次时，不再由外层同输入放大为400次。ASR不可用不等于声音通过，也不使已经可解码的视频消失。下载、解码、媒体来源和实际尾帧绑定仍是硬要求。
- schema117 将有重试能力的节点配置统一为20次总尝试（包含首次），大纲内部修正和分镜父子分段共享生成预算。相同诊断调整修复指令，不再暗中提前退出；角色图主备模型共享预算，连接重挂保留同一请求键，正常视频轮询与来源URL切换仍按各自协议执行。次数只提供恢复空间，不替代错误分类和本地计算。

`passed` 用于现有流程路由，实际质量状态在 `qualityReview` 中区分 `passed`、`needs_attention`、`unavailable`、`rejected`。原模型报告保留，不将未知改为已完成，也不声称验过全片或口型。后续续拍和最终检查消费相同策略，保留真实视频与排程、实际尾帧的绑定。

原执行记录与原始生成物保持不变，修复从新记录继续。重复验收要包括真实的新生成请求，不能只重放缓存或只看单元测试。成功生成不能证明以后外部模型永不失败；本次验证的范围、实际视频与仍需人工查看的建议会随交付记录列明。

重复实测还发现并修复了四个跨节点问题：

- 合法空镜开场的 `initialCharacters: []` 被通用必填校验当成缺值。现在必填 JSON 区分“没有提供”与“明确提供空数组”，实际人物入场仍由服务端验证。
- 入场参考绑定沿用作者估计的 1.5 秒，正式动作排程为 2 秒。请求预处理先重新验证排程哈希，再从唯一匹配的入场动作派生参考窗口。原分镜不变，实际请求和响应保留调整依据；歧义、损坏排程与入场前说话仍阻断。
- 人物图允许布局差异后，下游还固定裁成三列。原则模式改用完整具名参考图，明确多视角属于同一人物，保留实际人数约束。
- 对象形式的质量建议被字符串过滤丢掉。现在原建议及其定位保留，支持 `message`、`problem`、`observation`、`suggestion` 等显示形式，有建议时明确显示 `needs_attention`。

真实第二次大纲的五个错误原本被逐项提前返回遮住。现在一次汇总可同时检查的错误；异空间的修复提示保留 `scene_cut` 和原声画，不诱导模型仅改成尾帧连续来掩盖空间差异。

第二轮实际尾帧续拍还暴露了生成与校验输入不一致：校验使用 `loop.previous.shot_script.worldState` 的可信投影，旧模板却读取不存在的 `video_shot.worldState`。四个真实候选因此反复把未知位置声明成已观察。现有模板修正字段，运行时也给保存的旧节点和每次修复请求追加同一份权威状态 JSON；错误同时返回具体字段、期望值和候选值。不自动改写作者正文，不把未知状态升级为观察事实，已确认位置、持物或动作的冲突仍阻断。

明确启用原则模式且已绑定真实尾帧的 cinematic 续拍，使用实际状态继承契约，不再要求两份画面描述逐字相同。补充一致的实景、机位说明不会阻断；`same_frame`、前镜 ID、首帧人物、在场名单、剧情单元、场所及已观察状态检查保留。严格模式和未实拍的规划分段仍执行原规则。
