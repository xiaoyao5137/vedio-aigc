## 当前流程

大纲、分镜、人物图片和成片的模型审查均为画布上的独立文本推理节点。验收策略与结构检查是可编辑代码；采证通过通用 HTTP 节点调用本地媒体服务。没有新增历史短剧专属的“质检节点类型”。兼容旧工作流的业务操作仍保留，当前生成链路不再隐式执行这些模型质检。

成片链路：生成 → 采证参数 → 解码/ASR/抽帧 → 数值预算与验收范围 → 逐帧独立观察 → 质量推理 → 代码验收 → 尾帧/下游。

- `acceptance`: `passedPath`、`retryFrom`、`maxAttempts`、`feedbackPath`。默认成片总尝试上限 4 次，大纲/分镜/人物图各 3 次；都包含首次。
- `errorRetry`: 匹配错误文本、复核起点及单独次数预算。无效或不确定报告先复核同一素材，默认最多 2 次；不会因 ASR/网络故障重新买视频。
- 成片报告字段错误回退到报告推理节点，保留已有画面观察。错误指出缺失的具体字段，例如 `pacingReview.lastMeaningfulActionSecond`；报告生成节点直接收到该修复意见。
- `mapInput`: 数组来源、单项变量、数量上限。逐帧串行推理，按单项记录模型流水和请求标识，避免多图互相干扰与请求突发。
- 重试反馈只发给回退的目标节点。新素材的独立观察不接收旧拒绝意见。成片修复指令限制 350 字符，模型被要求只写 200 字以内局部修复，不拼接整份失败报告或删减原剧本。
- 每个节点保留 `attempts`，包括候选、输入、失败输出；同一轮重试不会回退前一轮。达到上限保留所有候选并停在验收节点。
- 请求标识包含逻辑执行、节点、轮次、抽卡次数、复核版本、逐项下标；恢复同一次调用可复用已完成结果，新抽卡不能复用旧片。

## 验收口径

ASR 与 ffmpeg 只提供实际证据。语速计算在配置代码中按台词字数、标点停顿和 ASR 容差生成逐句 `allowedSpan`；推理报告必须逐句与该证据一致，不允许漏算容差后拒绝。ASR 置信度不是拖腔或发音错误的证据。明确超出预算的实际慢语速仍不能放行。

剪辑尾部按配置区间判断，0.3 秒是目标值，不能因 0.36 秒与它不精确相等而重拍。推理报告必须引用计算后的 `tailTiming`。通过后的输出保留供应商生成参数与首帧引用，并发布本次配置验收的人声结论，确保下一镜连续性检查能获得完整证据。

持续中的剧情单元明确列出 `deferredActions`；这些后续待拍动作不要求本镜提前完成。已结束单元仍须逐项满足原完成条件。道具审核逐人逐帧列证据，角色缺失、物件错乱等实质错误不能因语速合格而放行。没有逐帧音画口型检测，本次结果不声称具有该能力。

人物图片先生成候选，经独立采证/模型审核/代码验收后再归档，未通过候选不能进入复用库。史料审核保留逐场引文与正文的校对，以及配置代码中的已知行动主体/时代回归约束。
