# record-xspbe3：默认用户验收与第15轮恢复

## 故障原因

原记录在第15轮 `sanguo-shot-script`（索引471）耗尽五次生成。校验把同一明确群体“万余信众”和“万余跪拜信众”当作不同说话人，又把“万人齐声应和”等表演说明要求成逐字台词。候选为满足冲突条件而把说明写进音轨，造成新的文字不一致。

修复共同的群体引用和表演说明识别契约：只在原文、群体身份和完整台词均可唯一对应时归一，不删除台词，不把独立声部合并，也不把陌生角色映射为已命名角色。原始五份候选全部进行离线回放，实际 paid request 仍重新验证排程与演员绑定。

## 默认策略

三国工作流默认 `qualityDisposition=manual-review-v1`，页面展示“用户验收（推荐）”。现有严格质检可切换回来，保留此前配置预算；保存的旧执行结果和旧媒体不改写。

- 内容、史料表达、剧情覆盖、镜头连续性、人物形象、ASR及口型等检查保留报告和提示，不触发自动重拍。
- 每个审核模型最多调用一次；报告无法形成时标为 unavailable，交用户查看。
- 分镜可执行结构首次不通过时最多修复一次，即共两次生成。图片与视频不因质量判定自动抽卡。
- 缺失或损坏的实际媒体、不可执行的排程、错误引用、声部绑定和排程哈希等仍阻止执行，避免把无效输入送给供应商。
- 有效视频缺音轨、画面或内容欠佳时可以继续，保持原问题和测量值；不伪造听审通过、口型通过或完整观看。
- 命名人物仍使用冻结的原有声音。明确匿名群体的画内合唱采用供应商原生声音，标记 unbound / uncertain / manual-review-pending，不创建虚假单人音色。
- 下游拼接和整集验收遵守相同策略，避免上游放行后下游再次以相同质量问题阻塞。

`passed/canProceed` 在用户验收策略中表示技术上可以继续；`manualReviewRequired` 和 `needs_attention` 表示仍需用户看片决定是否重做。

## 用户操作

执行页“质检方式”选择“用户验收”。不满意某段时，在该轮节点详情的“本轮重做”选择重做起点，点击“创建本轮重做记录”，再“运行本轮”。从视频节点重做可复用此前分镜和图片；从分镜或首帧开始则重建相关下游产物。

重做创建可追溯的新记录，保留原执行和之前已完成的循环。被重做节点及其依赖下游失效；重新生成的片段需要重新进入拼接，避免混用旧成片。
