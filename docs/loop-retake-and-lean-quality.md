# 本轮重做与轻量质检

本次针对 `record-mp0ow5` 的失败落地：修复不一致的匿名群演校验，将质量偏好与确证缺陷分开，允许用户保留旧版本并从指定循环节点重做。

## 失败原因

第 9 轮 `sanguo-shot-script`（执行索引 273）已批准匿名弟子、百姓的真人场景，因此没有具名角色；旧连续性校验仍要求非空具名名单，造成 5 次候选都无法满足的冲突。修复统一分镜、实际尾帧继承和付费视频入口的资格判断：无名演员绑定到 `actorGroups`；不虚构角色参考图，也不允许删除仍在场的具名角色。

真实恢复还暴露出另一种模型错误：弟子的原对白和站立动作被绑定给百姓群体。校验继续阻止串角；诊断现在给出预期声部和实际绑定。只有批准源动作与唯一原台词能够确定主体时，才本地修正群体绑定，保留文字、动作、画外标记和其它声部。不能确定的情况仍交给生成修复，不能删台词过关。

匿名角色的明确画外对白通过独立角色原声轨生成、按原排程合入视频，并按源场景与角色名称保存稳定声音身份，无需伪造人物肖像。其音轨仍为角色对白；输出不宣称人工听审或口型通过。已有画内对白、否定或含糊的画外标记不能自动走这条路径。只有新创作且原义务未要求可见口型时，提示词才允许明确设计角色画外对白。

真实成片回归还定位到审核传输故障：Codex 的 WebSocket 连接重置提示被误当终止错误，在约 2 秒时打断重连。适配器现在识别实测重连与 HTTPS 回退诊断，等待同一请求完成；鉴权失败、真正终止、超时与不完整结果仍报错。该修复只需重跑审核，不重买视频。

另有 4 次历史视频回跳与环境声 ASR 有关。不可靠短转写曾被直接判为额外台词，或经审核模型重复引用后重新升级。技术检查和审核引用现在共享转写可信度判断；同一不可靠转写不能因为第二份报告复述而成为独立反证。

## 默认质检与重试

| 项目 | 行为 |
| --- | --- |
| 无媒体、无法解码、缺音轨、明显截断、严重画幅错误 | 保留硬校验 |
| 有当前素材与来源反证的身份、史实、核心事件错误 | 保留硬校验 |
| 高置信额外人声、实测大范围台词错误 | 保留硬校验 |
| 普通姿态、微表情、细小服饰差别、节奏和构图偏好 | 保留建议，不自动重拍 |
| 低置信环境声转写、采样未知、报告不可用 | 标记待人工查看，不声称质量已验证 |
| 默认审核及抽卡结果分支 | 各最多 2 次尝试，含首轮；达到上限保留结果和原因 |
| 人物图内部技术修复 | 单次节点执行最多 2 次；与结果分支、同请求传输恢复分别计数，不承诺所有底层请求合计不超过 2 次 |
| 结构化分镜生成与修复 | 仍保留独立的 5 次总预算；不通过删除原剧情来放行 |
| 已有逐帧观察、逐要求重复审查 | 原原则模式继续跳过，保留一次原则审查及真实采证 |

预算由 `principle-lean-v1` 配置标记管理，自动发现实际重试分支和生成目标，后续加载保留用户设置的 1–5 次预算。质检的 `canProceed` 表示流程可以继续；`needs_attention` / `unavailable` 与 `speechVerified=false` 保留未知边界，不等同于人工听审或完整视觉验收。

## 使用方法

1. 打开执行记录，选择需要调整的循环轮次。
2. 在节点检查中的“局部重做”选择起点，如分镜、首帧、视频生成或审核。
3. 点击“创建本轮重做记录”。此操作保存新记录并暂停，不提交生成请求。
4. 检查参数后点击“运行本轮”，或用“下一步”。运行本轮遵守已有断点，在下一轮之前停止；支持当前节点完成后暂停。
5. 预览片段；如仍不满意，可从同轮相应节点再次创建重做记录。

## 执行与历史约束

- 目标必须是所选 `loopGroupId + loopIndex` 内已执行节点；不能跨过此前未完成节点，也不能在执行中重做。
- 原记录、原始输出、分支历史及目标前的完成前缀保持；新记录保存来源、重做起点、影响实例及旧尝试。
- 目标及全后缀失效，包含后续轮次和最终合成。任意代码节点都可能读取 `loop.previous`，所以采用保守失效，不静默复用可能过期的尾帧和合成结果。
- 后续节点通过实际前缀重建输入与上一轮结果，不能从旧路由快照复活旧素材。
- 每次重做以新 `generationScopeId` 隔离模型请求；从同一历史记录重做多次也不会撞缓存。`requestScopeId` 保持原声音归档身份。
- 独立配音链的画面回执也包含本次请求标识：网络恢复可以复用同次已付费画面，人工重做会生成新画面。
- 本轮边界同时在外层循环和单步执行器的条件跳过逻辑检查，避免本轮尾部都是跳过节点时意外提交下一轮。
- 老拓扑和不兼容时长策略仍拒绝混用，需要从兼容恢复记录继续。
