# 历史视频质量修复与验收（2026-09-06）

这次修复针对 `STORYBOARD_COVERAGE_INCOMPLETE` 以及循环之间剧情、人物、道具和声音不衔接的问题。当前历史短剧默认工作流为 schema 59、质量规则 `2026-09-06-dynamic-v3`。原有模型凭据和用户角色资产保留。用户已拒绝旧规则下的全部 11 段：尾部拖沓、说话慢、第一场尚未回应就切到下一场。旧自动通过记录不能作为当前成片质量验收。

## 当前节奏与转场规则

- 时长由台词、不能与对白并行的必要动作、0.3–1.2 秒自然反应和 0.3 秒剪辑余量估算，向上取整到 3–15 秒；自然语速按约 4.5 汉字/秒预算。超过上限必须保留剧情拆成连续段，不能加速台词或删掉硬锚点。
- 已移除大纲、结构校验、视频参数、Kling 提示加固器中覆盖为 15 秒的行为，以及强制末尾 1.5 秒闭口静止的要求。视频检查按实际片长抽帧，合成按实际片长累加。
- 大纲声明剧情单元、动作及回应完成条件、是否收束；分镜记录动作结果、对手回应和待完成事项。未收束的单元必须接同场真实尾帧，完成后也要实际画面与语音审核提供收束证据，才允许换场。不能只凭 `cut` 标记或历史因果说明换场。
- 剧情收束与节奏独立核对大纲原完成条件、实际画面观察和ASR，不将附带点头或手部遮挡扩展成新的硬条件。逐项区分完成、实际缺失、证据不足；未知不等于缺失，不能触发付费重拍。身份、道具、场景和实际尾帧仍需独立画面检查。
- 动作审核报告若一面声称“没有矛盾、无需修复”一面报失败，只复核原报告一次，不因此连续重写剧本。动态分镜写作最多三次，失败保留错误并停止媒体提交。
- 本次实片回归限定原第一、二镜，每镜一版；复用角色图片，不自动重拍或扩展整集。`scripts/history-pacing-regression.mjs` 使用生产提示、验证器和真实可灵请求；实际证据保存在 `logs/quality-regression/dynamic-first-pair/`。该报告范围只是前两镜，不代表完整工作流已经验收。
- Ofox 在全部入口禁用；生图只用可灵，文本和画面审核用用户指定的 Doro Claude（`doro.lat`）。

## 已定位的原因

1. **素材检索拿到了目录。** 原失败执行将《后汉书》目录作为史料，目录不能支持具体事件、对白归属和因果关系。现在识别目录、跟进相关章节或使用正文来源，并要求独立审查提供逐场、可在正文找到的引文。拟制对白须明确标注。
2. **分镜错误互相遮蔽。** 覆盖检查和对白时长检查以前先遇一项就停止，三次重试没有同时修复所有问题。现在保存被拒候选，联合诊断、局部修复；确实超时则按剧情节拍顺序拆分。复杂节拍可跨相邻段，但每个硬锚点必须明确分配且不能漏失。标题和引用元数据不再充当实际剧情覆盖。
3. **循环带入了错误状态。** 跳过的首帧分支残留前轮结果，拆分场景重带整份原始义务，预生成后续段使用尚未发生的旧上下文。现在每轮清理子节点结果，只从明确的 `loop.previous` 接续；拆分段只承担自己的剧情，后段在前段真实成片验收后生成。
4. **视频适配器覆盖了已审定的表演。** 原来的同期声“加固”会改写动作、视线、机位和结尾情绪。现在只添加声音约束，保留剧情；声明入场的人物也保留身份参考。超过模型提示长度时拒绝付费提交，不再截断剧情中部。
5. **最终构图没有送进视频模型。** 原节点虽生成 `lastFramePrompt`，实际视频提示却遗漏它。现在生产与实片回归共用提示构建函数，明确传入完整动作、运镜、片尾人物与道具构图，关闭自动多镜头。
6. **自检只检查请求或模拟返回。** `sound=on`、URL 或模拟器成功都不能证明真实视频质量。新检查解码成片、检查音轨、识别实际台词与时间窗、采样审查画面、比较连续镜头首帧和前镜实际尾帧。最终验证要求所有证据齐备。
7. **常驻服务仍可能运行旧代码。** 关闭热更新的本地服务必须重启才能加载后端修改。现在前后端及实片回归核对质量版本，版本不一致时阻止生成。
8. **角色定妆与分镜互相冲突。** 分镜过去在读取角色库之前设计外观，可能把既有角色服装互换。现在先读取稳定身份外观，生成和审查共同遵守；旧画面站位不进入固定身份属性。
9. **付费任务接受后未及时记录。** 现在取得服务商任务 ID 就落库，提供 GET 恢复查询；相同节点请求遇到未完成任务时优先恢复。可播放但验收失败的片段保留供复查。

明确的实片质量失败会携带具体问题自动重拍一次；两次均失败则停止后续镜头。网络、转写运行环境、无效审查报告等故障不触发额外付费重拍。

视觉审查先逐帧独立观察（不提供剧本和姓名），再对照剧本判断。相符证据被误判成错误、把“前伸”姿态当作仍在运动、要求无声图片识别“拜帖”用途等报告错误会先复核，不能直接触发重拍。

## 检查范围

- 分镜：每段至多引入 2 个完整三视图身份，更多必要人物分段加入，不静默裁掉参考图；动态 3–15 秒、对白时长、实际剧情锚点、人物入场、剧情单元收束、跨地点转场、前后镜身份与状态。
- 内容：来源正文、逐场引文、史实与合理拟制边界；审查报告不合规则修复报告，不能误当成剧情失败。
- 成片：完整解码、实际时长（容差 0.5 秒）、画幅、有声且不接近静音。
- 声音：本地 Whisper small 转写，拼音序列比对，检查完整台词、顺序、拖慢和片尾截断；窗口偏移保留警告并结合动作审核，动态片只预留 0.3 秒剪辑余量。拼音比对降低专名同音转写误报，但不是人物发音的专家鉴定。
- 连续性：后一段用前一段的真实尾帧；缩小后首尾像素平均差不超过 0.10；视觉审查要求片尾可见人物集合与剧本一致，并审查道具归属和构图。
- 视觉审查是采样检查，不等同于逐帧人工审片或精确口型同步认证。输出明确保留 `lipSyncVerified: false`，不得将其宣传为已验证口型。

## 复验

```bash
npm install
npm run setup:quality
npm test
npm run lint
npm run build
# 重启本地服务后执行真实文本回放（消耗已配置的文本模型额度）
npm run test:history-replay
# 两段连续实片回归（消耗视频模型额度；已有结果缓存后不重复提交）
node scripts/history-media-smoke.mjs
# 用户反馈后的动态节奏及收束回归，仅原前两镜，每镜一版
node scripts/history-pacing-regression.mjs
```

`npm run test:smoke` 只验证模拟流程连线，不是历史视频生产质量证明。

实际结果、审查报告和转写放在 `logs/quality-regression/`，可播放成片与尾帧在 `public/generated/`。这些运行产物不提交到 Git。真实验收结论见本次最终交付记录，不能仅凭测试数量推断成片已经通过。
